================================================================================
THE TASK
================================================================================

A domain whose contracts live in more than one file generates code that does not
compile. Fix it so a domain can be split across files.

It is already written up, by the person who hit it, in:

    docs/CLI_REFERENCE.md   — the section "Known defect: a domain split across
                              two files generates broken imports"

Read that first. It names the cause and proposes the fix. You are not obliged to
agree with the proposal — if you find a better one, say so and explain — but you
should start from it rather than rediscovering the bug.

================================================================================
HOW IT FAILS
================================================================================

`src/cli/commands/GenerateCommand.ts`, in both `generateToolRegistry` and
`generateCLI`:

    const domainFiles = files[m.domain];
    const alias = aliasMap[domainFiles[0]!]?.alias;   // ← always [0]

Every contract in a domain is emitted against whichever file of that domain was
scanned first. A contract living in any *other* file of the domain generates a
reference to a symbol that file does not export:

    error TS2551: Property 'siteComposeContract' does not exist on type
    'typeof import(".../cdn/contracts/release.contract")'.
    Did you mean 'composeContract'?

Note what makes it nasty: the error is legible, names a real symbol, and
suggests a similar one — so it reads as "rename your contract" rather than "the
generator picked the wrong file". The person who hit this worked around it by
putting one file per domain, which is a fine convention and a bad requirement.

================================================================================
THE FIX, AS PROPOSED
================================================================================

`discoverContractsAndEvents` already knows which file it read each contract
from, and throws that away. Carry it on the `ContractDiscovery` entry and use
it, rather than looking the file up by domain afterwards.

Domain → files is the wrong index for the question "which module exports this
contract". Contract → file is the right one.

Check whether `generateEvents` has the same defect. It probably does; the same
lookup pattern appears there.

================================================================================
WHAT DONE LOOKS LIKE
================================================================================

A test that would have caught it. That means a fixture with **one domain across
two files** — the shape nothing in this repository currently has, which is
exactly why the bug survived — and an assertion that what comes out imports each
contract from the module that actually exports it.

Asserting on the generated *text* is acceptable here and is not usually. The
generator's output is a file that has to compile, so the useful check is that
each emitted reference names a symbol its module exports.

`npm test` must stay green. There are 318 tests on master; the branch
`dispatch/2` has 338, so check which base you are on and do not read a
difference as a regression.
