================================================================================
WHAT IS ALREADY KNOWN — do not re-derive this
================================================================================

The first cause is found and already fixed in commit d54eff0. The test helpers
rewrote the Mongo URI with:

    uri.replace(/\/[^/?]+(\?|$)/, `/${dbName}$1`)

which is only correct when the URI already has a database path. Given
`mongodb://localhost:27017` it matches `/localhost:27017` and produces
`mongodb://mesh_test_xxxxxx` — replacing the HOST with the database name. The
driver then burned its whole server-selection timeout resolving a hostname that
does not exist, and every affected suite reported a jest hook timeout rather than
a bad URI. That is why it looked like a connectivity problem for three rounds.

It is not a connectivity problem. A CI step that connects to the very same URI
with the driver directly pings in 35ms.

`withTestDatabase()` in src/testing/TestHelpers.ts replaced that regex with URL
parsing and is correct for all URI shapes including credentials and query
parameters. Four call sites now use it.

That took the suite from 71 failures to 31.
