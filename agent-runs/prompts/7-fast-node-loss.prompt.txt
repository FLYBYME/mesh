================================================================================
THE TASK
================================================================================

**A dead node must be known dead within two seconds.**

Clean disconnect already is: the socket closes, `TransportManager` emits
`peer:disconnect`, `MeshOrchestrator.handlePeerDisconnect` calls
`registry.unregisterNode` immediately. Verify that and leave it alone.

Unclean loss — power cut, pulled cable, partition — is the case. No FIN, so no
`peer:disconnect`, and detection falls to the sweep:

    src/core/Registry.ts:87    this.ttl = options.ttl || 30000;
    src/core/Registry.ts:198   setInterval(() => this.pruneStaleNodes(this.ttl), 5000);

**Lowering `ttl` alone does not fix it** — the sweep period is that hardcoded
`5000`, so `ttl: 2000` still detects at up to 5 seconds. Both numbers have to
move together, and a configuration that lets them contradict each other is a
configuration somebody will get wrong.

**Choose the mechanism and justify it.** Two candidates:

  * a shorter application heartbeat plus a sweep derived from the ttl
  * WebSocket **ping/pong** with a timeout at the transport, which detects a
    dead peer without adding registry gossip

I would pick ping/pong if the transport supports it, because it costs no
registry traffic and it is what the layer is for — but you are the one reading
the code. Say which you chose and why. If you choose ping/pong, the heartbeat
sweep still needs its interval untangled from the hardcoded `5000`, because it
remains the backstop.

**Do not make the default aggressive for everyone.** The fleet is seven nodes and
a one-second heartbeat there is nothing; a large mesh is a different question and
this repository does not get to assume the small case. Fast detection should be
*configurable and used by the fleet*, not imposed on every deployment. If you
disagree, argue it in your plan rather than silently changing a default.

Watch the two multipliers in `pruneStaleNodes`: unavailable at `age > ttl`,
deleted at `age > ttl * 2`. Whatever you do, a node must not be *deleted* so
eagerly that a brief hiccup loses its registry entry and its service list —
`heartbeat()` already documents that a heartbeat must be able to bring a node
back, and that property has to survive your change.

A NOTE ON TESTS. Four times in these repositories a test has been written that
encodes a known bug as intent — with a comment correctly explaining the bug and
an assertion demanding it. If a test you are about to write needs a comment
explaining why the behaviour is wrong, fix the behaviour or leave the test out.

Timing tests are the flakiest thing anyone writes. Prefer fake timers or an
injected clock over `sleep`. A test that passes on an idle laptop and fails in CI
is worse than no test, and this suite already has load-related flakiness.
